# 图片判断实验：24 张本地测试

这四个文件是一套系统：

- `server.js`：Node.js 后端，提供页面、图片、答题接口，保存记录并导出 CSV。
- `index.html`：参与者答题页。填写专业、勾选同意后，判断图片、选择信心分数，最后估计正确率。
- `admin.html`：管理页，查看参与者记录、每题答案及原因，下载汇总和逐题 CSV。
- `analysis.html`：分析页，汇总人像／风景、彩色／灰度、真实／AI 等分组结果。

## 启动

在 macOS 上双击 `start.command`，保持打开的终端运行。也可以在本目录执行：

```sh
./start.command
```

脚本优先使用已安装的 Node.js，否则使用本机 Codex 自带的 Node.js。无需 `npm install`，没有第三方依赖。如果两者都没有，安装 Node.js 18 或以上版本。

- 答题页：<http://127.0.0.1:3000>
- 管理页：<http://127.0.0.1:3000/admin>
- 分析页：<http://127.0.0.1:3000/analysis>
- 管理用户名：`admin`（后端只核对密码）
- 默认本地测试密码：`local-test-123`

不要直接双击 HTML 文件；提交和保存需要通过后端访问。按 `Ctrl+C` 停止，重新运行脚本即可启动。若提示 `EADDRINUSE`，说明端口已有服务占用，可先打开上面的地址，或运行 `PORT=3001 ./start.command`。

如果已安装 Node，也可以直接运行：

```sh
ADMIN_PASSWORD='你设置的密码' node server.js
```

默认仅本机可访问。启动脚本的固定密码只用于本地测试。

## 当前的 24 张图片

后端启动时自动扫描：

```text
image/
  portrait/
    AI/      6 张 AI 人像
    real/    6 张真实人像
  landscape/
    AI/      6 张 AI 风景
    real/    6 张真实风景
```

支持 `.jpg`、`.jpeg`、`.png`、`.webp`，扩展名不区分大小写，图片无需改名。真实／AI 标签来自所在文件夹，请自行确认归类准确。全部图片会先预加载，加载成功后才能开始。

每位参与者看 24 张不同图片，每张只出现一次。人像 AI、人像真实、风景 AI、风景真实四组各有 6 张，每组随机分配 3 张彩色和 3 张灰度。出题顺序随机，页面和后台的题数随图片数量变化。

彩色原图可配套一个同目录灰度文件，文件名为原文件名加 `_gray`，例如 `portrait1.jpeg` 对应 `portrait1_gray.png`。`_gray` 文件不会被当作独立题目；某张图没有灰度文件时会使用彩色原图。

AI 的 high/mid/low 逼真度尚未标注，导出的 `ai_realism` 留空，不会根据文件序号猜测。不要在参与者答题过程中改动图片；应等本轮完成后再变更。每组数量为偶数时可以做到该组彩色／灰度各半。

## 测试及查看数据

1. 打开答题页，填写专业（试跑可填 `TEST`），勾选同意，点击 Start。
2. 完成 24 题，每题选择 Real photo 或 AI-generated，并选择 1–5 信心分数。选择 AI-generated 时必须填写原因；选择 Real photo 时原因选填。
3. 可以点击 Previous 返回之前的题目。已有答案会恢复，重新作答后后台和 CSV 只保留该题的最终答案。
4. 在最后一题选择估计正确率（0%、25%、50%、75%、100%），点击 Submit，等待 `Your responses are saved ✓` 再关闭页面。
5. 打开管理页，查看 Done 是否为 `24/24`、状态是否为 `completed`；点击参与者行展开逐题记录。
6. 点击 Participants CSV 或 Trials CSV 导出。前者每人一行，后者每题一行，包含回答、真实标签、彩色／灰度、正确与否、信心、原因及反应时。管理页中的 Analysis 可打开分析页面。

数据保存在本机 `data/events.jsonl`，服务重启后仍保留。记录不会发往外部服务。答题中不要刷新或关闭页面：已提交的记录保留，但当前页面不支持断点续答，重新开始会生成新的参与者 ID。自动验证使用独立的临时数据目录，不混入这里的记录。

正式收集前，将答题页的 `[researcher email]` 替换为实际联系邮箱，并检查同意说明和研究方案。当前版本可用于本地流程测试，不应把测试记录混入正式样本。

图片支持点击放大，可点击 Close、遮罩或按 Esc 关闭，灰度图片放大后仍保持灰度。看大图的时间包含在该题反应时内。

结果页和后台的估计值以百分比显示，Difference / Gap 以百分点（pp）显示。汇总 CSV 新增 `self_estimate_percent` 和 `estimate_minus_actual_pp`。原有 `self_estimate` 与 `estimate_minus_actual` 保留题数单位（百分比按总题数折算，可能有小数）；旧记录会自动换算为百分比显示，换算时不改写原始日志。

## 删除参与者记录

登录 `/admin` 后，在记录右侧 Actions 列点击 Delete，核对确认框中的参与者 ID 后确认。取消不会改动记录。

删除会移除该参与者的基本信息、全部逐题答案、原因及结果，更新统计和之后导出的 CSV，并从 `data/events.jsonl` 中清除对应记录。正在答题的参与者被删除后无法继续提交。删除不可撤销，重启后也不会恢复；编号继续递增，不会复用被删除的 ID。其他参与者记录不受影响。

已经下载的 CSV 或服务器备份不会随之被删除，需要自行管理。

## Render 部署

仓库中的 `render.yaml` 配置一个新加坡区域的免费 Node.js Web Service，适合公开演示和小范围测试。

1. 登录 Render，授权其访问 GitHub 私有仓库 `unius723/ai-detection`。
2. 使用 New → Blueprint 选择该仓库的 `main` 分支，读取根目录的 `render.yaml`。
3. 核对服务配置后创建。部署状态变为 Live 后，使用 Render 提供的网址访问答题页，网址后加 `/admin` 访问后台。

后台用户名仍为 `admin`。云端密码由 Render 自动生成，在该服务 Environment 页面查看 `ADMIN_PASSWORD`；不要使用本地测试密码登录云端。密码不保存在 GitHub 中。

答案临时保存在 `/tmp/ai-detection-data/events.jsonl`。请及时导出 CSV，并保留所需备份。此版本使用文件保存记录，保持单实例运行。

已关闭提交后的自动部署，避免收集答案期间因更新产生服务中断。后续更新请在无人答题时使用 Manual Deploy。

Render 免费服务空闲约 15 分钟后会休眠，下一次访问需要等待它重新启动。免费服务没有持久化磁盘；休眠、重启或重新部署都可能清空参与者记录。因此免费版只适合测试，测试期间请及时在管理后台导出 CSV。正式收集数据时应改用带持久化磁盘的付费服务，或把记录存入外部数据库。
